総支給と手取りの **差** だけ残しても、中身が保険料なのか税なのかは分かりません。差が大きく動いた月に、自分はまず **健康保険料** と **厚生年金保険料** を見ます。ここではその2つに絞ります。

総支給・手取りの話は [差の記事](/blog/salary-gross-takehome-gap-howto)、PDFの取り込みは [PDFの記事](/blog/salary-pdf-import-takehome-howto) に任せます。例は **[給与明細管理](/blog/app-intro-salary)** ですが、ノートや表計算でも同じです。

まだ分かっていないこと: 会社ごとの表記ゆれ（「健康」「健康保険」「協会けんぽ」など）は自動で揃えきれません。**明細に書かれた本人負担額** を正とします。

## 明細のどこを見るか

多くの明細では、控除の欄に次が並びます。

| よくある表記 | 見るポイント |
| --- | --- |
| 健康保険料（健康保険） | **本人負担**の金額。会社負担は別欄／非表示のことが多い |
| 厚生年金保険料（厚生年金） | 同上。合計欄だけだと内訳が消えることがある |
| 雇用保険・介護保険など | 今回の必須ではない。余裕があれば後から足す |

失敗しやすい点:

- **会社負担と本人負担を足してしまう** — 記録するのは基本的に本人負担
- **賞与月だけ保険料の出方が違う** — 通常月と分けて見る（[賞与の記事](/blog/salary-bonus-record-howto)）
- **表記が英語・略語だけ** — 金額の並びと「控除」見出しで当たりをつける。分からなければその月は手取り差だけでもよい

料率や等級の計算は会社・協会けんぽ側の話です。ここでは **明細に印刷された数字を残す** だけにします。

## 毎月、何を残せば足りるか

最初から控除を全部転記する必要はありません。

| 項目 | なぜ必要か |
| --- | --- |
| 年月（支給月） | 推移の軸 |
| 総支給・手取り | 差の土台（[差の記事](/blog/salary-gross-takehome-gap-howto)） |
| 健康保険料（本人） | 差の中で動きやすい柱のひとつ |
| 厚生年金保険料（本人） | 同上 |
| （任意）雇用保険・介護など | 余裕が出てから |

必須を増やしすぎると続きません。自分は **総支給・手取りに加え、健保と厚生年金の2つ** を足す運用にしています。それ以外は未取得の月があってもよい、と決めています。

## 続け方の目安

| タイミング | やること | 目安 |
| --- | --- | --- |
| 給与日〜数日 | 健保・厚生年金を転記（またはPDF取り込み後に確認） | 1〜3分 |
| 記録直後 | 先月と極端に違うかだけ見る | 30秒 |
| 等級・標準報酬が変わった月 | メモ1行（理由が分かる範囲で） | — |
| 四半期に1回 | 推移をざっと見返す | 5分 |

「正しい保険料か」を証明する作業ではありません。**先月と違ったら気づく**ためのログです。

## 向いている人／向いていない人

向いている例:

- 差だけ見ていて、中身が気になり始めた
- 昇給や標準報酬の改定のあと、手取りの感覚がずれた
- 家計簿まではやらないが、大きい控除だけは残したい

向いていない例:

- 社会保険料の正確な計算・還付・申告をメモで完結させたい
- 会社の給与計算・複数人の一括管理が目的
- 社内ルールで給与情報を個人端末に置けない

## アプリでの記録（給与明細管理）

**[給与明細管理](/blog/app-intro-salary)** では、明細ごとに総支給・手取りを残し、PDF・写真・手入力に対応します。保険料の専用計算機能はありません。明細から読めた金額を、手修正も含めて **自分用の記録** として残す用途です。

データは端末内にAES-256で暗号化し、外部サーバーへ送りません。税・社保の正確な計算や申告を保証するものではありません。

## よくある質問

### 介護保険や雇用保険は必須ですか？

最初は不要です。健保と厚生年金で差の動きの多くはつかめます。気になった月から足せば足ります。

### 会社負担も残すべきですか？

家計の記録なら、まず本人負担だけで足ります。会社負担は明細に出ないことも多いです。

### PDFで数値がずれたら？

手で直します。[PDF取り込みの記事](/blog/salary-pdf-import-takehome-howto) を参照してください。
