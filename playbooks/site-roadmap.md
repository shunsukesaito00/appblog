# Site Roadmap（個人開発ラボ）

エージェントが **次の開発提案** を出すときは、本ロードマップを参照し、**いまどのフェーズか**を踏まえて **1件だけ** 提案する。

## 前提（ゼロに近い現実）

提案は次の事実を **既定** とする。盛らない。

| 指標 | 目安（2026年8月時点） | 含意 |
| --- | --- | --- |
| アプリ AdMob | 月 **$1未満〜2** 台（7月 **$0.91**） | 収益化は「検証」段階。増収施策より **DL・再訪・更新再開** が先 |
| App Store DL | 月 **〜300**（1日 **〜10**）・7月は未取得 | ASOは **1アプリ・1キーワード** に絞る |
| サイトアクセス | **ほぼゼロ**（GA未確認でも小さい想定） | SEO記事は **量より1本の検索意図** |
| AdSense（サイト） | **審査未通過** | 再申請は **流入がついてから**。今は優先しない |
| ブログ記事 | 収益報告が多い | 新規は **How-to・悩み解決** を優先。月次レポートは **月1本まで** |

**提案で避けること:** 「月5万」「収益拡大」「AdSenseすぐ再申請」「アプリ本数を増やす」「記事を量産」、**App Store Connect 上の説明文・スクショ編集をユーザーに求めること**。

## 現状スナップショット（2026年8月時点）

- **済:** 収益報告（〜7月・4〜7月損益）、アプリ紹介4本、分析1本、給与明細How-to4本＋`/guides/salary`、writing-voice、トップ数字中心化、About連絡先
- **ボトルネック:** サイト検索流入なし、AdSense却下、収益報告偏重、**6〜7月はアプリ更新ほぼなしでAdMob低下**（7月 **$0.91**）、DLは給与明細集中
- **収益（2026-07）:** AdMob合計 **$0.91**・表示 **938**（給与明細 $0.60 / 694）。比較期間 $1.24。DLは未取得。記事: `/blog/revenue-report-2026-07/`
- **コンテンツ:** 収益報告以外の厚い記事は分析＋How-to4本で **5本**（フェーズ4目安クリア）。ガイド／How-to本番は HTTP 200・sitemap掲載
- **計測（要約）:** **2026-08-02:** `/guides/salary`（How-to4本）と社会保険How-toは本番 **HTTP 200**・sitemap掲載済み。`site:...`（PDF/手取り差/賞与/guides）は **ヒットなし（未登録寄り）**。**robots.txt 検証済**。残るのは SC の URL 検査（ユーザー操作）と GA PV（`playbooks/ga4-setup.md`）
- **ASO（要約）:** サイト側の説明文正本は `apps.ts`（`npm run store:lead`）に残すのみ。**App Store Connect 上の説明文編集・提出は行わない**（運営方針: ストアアプリ側の編集を求めない）。公開反映確認（`store:verify`）も次案に含めない。アプリ成長は **サイト流入・How-to・アプリ本体の小さな更新** 側で進める
- **導線:** グローバルナビ・トップ・`/blog`・`/apps`・フッタから `/guides/salary`（How-to4本）、分析・収益・紹介から How-to へリンク済み

## 提案の出し方（1件のみ）

1. **フェーズ:** 上表（0〜5）のどれか
2. **なぜ今か:** 前提の数字に触れ、なぜ他より先か（2〜3文）
3. **やること:** 最大 **2つ**（ゼロ前提では盛らない）
4. **完了条件:** 測定可能な1行（例:「記事1本公開」「週次PVを1回確認」）
5. **コピペ用プロンプト:** **1文**（そのまま貼れる）

**優先の選び方:** フェーズ番号が **小さい** 方。同フェーズなら **計測 → 信頼性 → 最初の1記事 → ASO1変更** の順。

**待ち期間中のルール（必須）:**

- `store:verify` や Connect 貼付を次案にしない（ストア側編集は対象外）
- Connect / Search Console / GA ログインなど **ユーザー操作が必要な待ち** があるとき、「次の開発提案」にその待ちタスクを置かない（繰り返し「実装して」で詰まるため）
- 待ち中の次案は **エージェントだけで完結** するものに限る（記事リンク、roadmap 整理、本番 HTTP 確認など）

## コピペ用プロンプトの書き方

- 収益・PV・DLの **現状を一文で書く**（例:「サイト週次PVほぼゼロ、DL月300弱」）
- **1アプリ・1キーワード・1記事 or 1変更** に限定する
- 「pushして」だけ、リンク1本だけ、は単独提案にしない（他作業とセット）
- **ユーザー作業をゼロに近づける**（SC貼り付け・Connect操作を次案に含めない。待ちはカレンダーまで棚上げ）

### 例（この前提での良いプロンプト）

```
サイトアクセスほぼゼロ・AdMob月$1台・DL月300弱の前提で、給与明細管理に絞り「給与明細 PDF 取り込み 手取り」向けのHow-to記事を1本（収益自慢なし・実務の注意点中心）作成し、記事末尾と/app-intro-salaryからApp Storeへ1導線に統一。Aboutに連絡先を1行追加してpushして。
```

### 例（避けるプロンプト）

```
AdSense再申請のため記事を5本追加し、全アプリのASOを一括改善して。
```
（流入も収益もない段階では早い・分散する）
