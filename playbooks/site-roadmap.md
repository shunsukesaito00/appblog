# Site Roadmap（個人開発ラボ）

エージェントが **次の開発提案** を出すときは、本ロードマップを参照し、**いまどのフェーズか**を踏まえて **1件だけ** 提案する。

## 前提（ゼロに近い現実）

提案は次の事実を **既定** とする。盛らない。

| 指標 | 目安（2026年7月時点） | 含意 |
| --- | --- | --- |
| アプリ AdMob | 月 **$1〜2** 台 | 収益化は「検証」段階。増収施策より **DL・再訪** が先 |
| App Store DL | 月 **〜300**（1日 **〜10**） | ASOは **1アプリ・1キーワード** に絞る |
| サイトアクセス | **ほぼゼロ**（GA未確認でも小さい想定） | SEO記事は **量より1本の検索意図** |
| AdSense（サイト） | **審査未通過** | 再申請は **流入がついてから**。今は優先しない |
| ブログ記事 | 収益報告が多い | 新規は **How-to・悩み解決** を優先。月次レポート追加は後回し |

**提案で避けること:** 「月5万」「収益拡大」「AdSenseすぐ再申請」「アプリ本数を増やす」「記事を量産」。

## 提案の出し方（1件のみ）

1. **フェーズ:** 上表（0〜5）のどれか
2. **なぜ今か:** 前提の数字に触れ、なぜ他より先か（2〜3文）
3. **やること:** 最大 **2つ**（ゼロ前提では盛らない）
4. **完了条件:** 測定可能な1行（例:「記事1本公開」「週次PVを1回確認」）
5. **コピペ用プロンプト:** **1文**（そのまま貼れる）

**優先の選び方:** フェーズ番号が **小さい** 方。同フェーズなら **計測 → 信頼性 → 最初の1記事 → ASO1変更** の順。

## コピペ用プロンプトの書き方

- 収益・PV・DLの **現状を一文で書く**（例:「サイト週次PVほぼゼロ、DL月300弱」）
- **1アプリ・1キーワード・1記事 or 1変更** に限定する
- 「pushして」だけ、リンク1本だけ、は単独提案にしない（他作業とセット）

### 例（この前提での良いプロンプト）

```
サイトアクセスほぼゼロ・AdMob月$1台・DL月300弱の前提で、給与明細管理に絞り「給与明細 PDF 取り込み 手取り」向けのHow-to記事を1本（収益自慢なし・実務の注意点中心）作成し、記事末尾と/app-intro-salaryからApp Storeへ1導線に統一。Aboutに連絡先を1行追加してpushして。
```

### 例（避けるプロンプト）

```
AdSense再申請のため記事を5本追加し、全アプリのASOを一括改善して。
```
（流入も収益もない段階では早い・分散する）
