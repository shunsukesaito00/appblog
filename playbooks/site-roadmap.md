# Site Roadmap（個人開発ラボ）

エージェントが **次の開発提案** を出すときは、本ロードマップを参照し、**いまどのフェーズか**を踏まえて **1件だけ** 提案する。

## 前提（ゼロに近い現実）

提案は次の事実を **既定** とする。盛らない。

| 指標 | 目安（2026年7月時点） | 含意 |
| --- | --- | --- |
| アプリ AdMob | 月 **$1〜2** 台 | 収益化は「検証」段階。増収施策より **DL・再訪** が先 |
| App Store DL | 月 **〜300**（1日 **〜10**） | ASOは **1アプリ・1キーワード** に絞る |
| サイトアクセス | **ほぼゼロ**（GA未確認でも小さい想定） | SEO記事は **量より1本の検索意図** |
| AdSense（サイト） | **審査未通過・有用性不足で却下** | **再申請はまだしない**。合格しやすい土台（有用記事・信頼性・インデックス）だけ先に進める |
| ブログ記事 | 収益報告が多いが、How-to・分析で緩和中 | 新規は **How-to・悩み解決**。月次レポート追加は後回し |

**提案で避けること:** 「月5万」「収益拡大」「AdSenseすぐ再申請」「アプリ本数を増やす」「記事を量産」「ASO verify 連打」。

## 現状スナップショット（2026年7月時点）

- **済:** 収益報告複数月、アプリ紹介4本（うち借入返済は実務注意を厚くした）、分析1本、給与明細How-to**3本**、ヒーロー実態化、プライバシー更新、About連絡先、収益報告導線、運用 playbook、主要記事→How-to内部リンク、トップで実務記事前面化

- **〜7/16 の作業枠:** 上表 A〜D を **1件ずつ** 進める（ASO verify だけ日付厳守）
- **A2（2026-07-14）:** トップ／ブログ一覧で How-to・分析を収益報告より前面に配置
- **C1（2026-07-14）:** `/blog/salary-bonus-record-howto/` 追加。本番 HTTP 200

## 提案の出し方（1件のみ）

1. **フェーズ:** 上表（0〜5）または A〜D の番号
2. **なぜ今か:** 前提の数字に触れ、なぜ他より先か（2〜3文）
3. **やること:** 最大 **2つ**
4. **完了条件:** 測定可能な1行
5. **コピペ用プロンプト:** **1文**

**優先の選び方（〜7/16）:**

1. **A1続き**（`app-intro-workout` など残りの厚み）を1本  
2. **C2**（給与明細系の App Store CTA 揃え）  
3. 計測の確認（`site:`／HTTP）は週1まで  
4. ASO verify は **7/17以降** のみ

**待ちルール:**

- Connect／SC／GA ログインが必要な待ちを、次案の単独テーマにしない  
- `store:verify` は **2026-07-17 以降**だけ  
- AdSense **再申請**はフェーズ5まで提案しない  

## コピペ用プロンプトの書き方

- 現状を一文（週次PVほぼゼロ、AdMob月$1台、DL月300弱、AdSense未通過）
- **1アプリ・1キーワード・1記事 or 1変更** に限定
- ユーザー作業をゼロに近づける（SC／Connect操作を必須にしない）

### 例（〜7/16・良い）

```
サイトアクセスほぼゼロ・AdSense未通過の前提で、給与明細の未カバー意図「賞与を給与明細アプリにどう残すか」のHow-toを1本（収益数字なし）作成し、既存のPDF/ギャップHow-toとapp-intro-salaryから相互リンク。buildしてcommitしてpushして。
```

### 例（避ける）

```
AdSenseを今すぐ再申請し、全アプリのASOと記事を5本追加して。
```
